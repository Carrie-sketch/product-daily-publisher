# 逐步执行清单

从第 1 步开始。每步先做检查，再行动。检查不通过就停下，列出缺的项，等使用者补充。不要跳步，不要猜测，不要在检查通过前发文。

## 第 1 步：确认技能已就位

检查：

- 技能目录存在，且能读到 `SKILL.md`、`templates/`、`references/steps.md`。
- 目录里没有真实密钥、账号、短链、内网地址。

要做：

- 若技能不在 `~/.claude/skills/product-daily-publisher/`，复制过去。
- 告诉使用者：接下来会逐项收集配置，缺一项就停。

完成标准：技能目录可读，且没有别人的隐私文件。

## 第 2 步：准备配置目录

检查：

- `~/.config/product-daily-publisher/` 是否存在。

要做：

- 不存在就创建，并把 `templates/` 里的文件复制进去。
- 不要覆盖使用者已经填过的文件。

完成标准：配置目录里有 `product.yaml`、`platforms.yaml`、`keywords.csv`、`keys.env`、`model.env`。后两个由 `bootstrap.py` 在使用者本机生成，分享包里没有这两个文件。

## 第 3 步：收集产品资料

向使用者逐项询问，写入 `product.yaml`。空着就不能发文。

必须补齐：

1. 产品名
2. 一句话介绍
3. 至少 1 个官方文档 URL
4. 允许写入文章的事实清单
5. 禁止编造或禁止提及的内容
6. 正文允许出现的链接：官网、文档、Demo、源码仓库。没有的留空
7. 标签分层和禁用标签。没有就留空，不要自行编标签

完成标准：以上 1 到 5 都已填写。6 和 7 可以留空，但必须明确是留空，不是漏问。

## 第 4 步：收集长尾关键词

向使用者要一份关键词表，写入 `keywords.csv`。

每一行必须有：

- `batch`：批次号，例如 B1
- `keyword`：一条长尾关键词
- `note`：可选备注

至少要有 2 条，因为默认每天发 2 个关键词。不要使用别人的关键词，也不要自己生成后直接开跑。可以提议一批，但必须等使用者确认后才写入。

完成标准：`keywords.csv` 至少有 2 条使用者确认过的关键词。

## 第 5 步：确认要开哪些平台

默认英文平台开启：主 dev.to、副 dev.to、主 CodeLegion、副 CodeLegion。

Zenn 和 Qiita 默认关闭。使用者明确说要开，才把 `platforms.yaml` 里对应项改成 `enabled: true`。

完成标准：`platforms.yaml` 里每个平台都是明确的开或关，没有含糊项。

## 第 6 步：收集密钥

只问「有没有、放在哪个文件」，不要让使用者把密钥贴进聊天。若已经贴进聊天，立即写入权限为 `600` 的配置文件，并提醒使用者作废后重发。

按已开启的平台收集：

| 开启的平台 | 要写入 `keys.env` 的项 |
| --- | --- |
| dev.to 主账号 | `DEVTO_API_KEY` |
| dev.to 副账号 | `DEVTO_API_KEY_2` |
| CodeLegion 主账号 | `CODLEGION_API_KEY`、`CODELEGION_USER_ID` |
| CodeLegion 副账号 | `CODLEGION_API_KEY_2`、`CODELEGION_USER_ID_2` |
| Qiita | `QIITA_TOKEN`、`QIITA_USER` |
| Zenn | `ZENN_REPO`、`ZENN_USER`、`ZENN_BRANCH` |
| 钉钉记录表 | `DINGTALK_BASE_ID`、`DINGTALK_TABLE_ID` |

另外必须有 `model.env` 里的 `LLM_API_KEY`。没有它只能停在生成之前。

要做：

- 从 `keys.env.example` 复制出 `keys.env`，从 `model.env.example` 复制出 `model.env`。
- 权限都设为 `600`。
- 只检查变量名是否存在、值是否非空。不要打印值。

完成标准：已开启平台对应的变量都非空，模型密钥非空，两个文件权限都是 `600`。

## 第 7 步：核对账号，不发文

用只读接口确认密钥属于使用者自己的账号。

- dev.to：读取当前用户，核对使用者给出的账号名。
- CodeLegion：读取当前用户 ID，核对 `CODELEGION_USER_ID`。
- Qiita：读取 authenticated user，核对 `QIITA_USER`。
- Zenn：确认 `ZENN_REPO` 能用使用者自己的部署密钥推送，且 Zenn 后台已关联该仓库。

任一账号对不上就停止。不要改密钥，不要继续发文。

完成标准：每个已开启平台都打印「账号核对通过」和账号名，不打印密钥。

## 第 8 步：准备记录表

记录表使用钉钉 AI 表格，不要改用别的表格。表必须建在使用者自己的钉钉里。

先检查有没有钉钉 CLI。没有就按 `references/dingtalk-cli.md` 安装并登录，再继续。

```bash
command -v dws || echo '未安装，先看 references/dingtalk-cli.md'
dws auth status --format json
python3 setup_table.py
```

`setup_table.py` 会创建「每日发文记录」和「发文记录」表。把返回的 Base ID、Table ID 写入 `keys.env` 的 `DINGTALK_BASE_ID`、`DINGTALK_TABLE_ID`。不要把登录令牌写入配置。


按下面的表头建列，名称必须一致，不要自行改名。未开启的平台也先建列，以后打开平台时不用改表。

| 表头 | 类型 | 说明 |
| --- | --- | --- |
| 关键词 | 文本 | 当天使用的长尾关键词 |
| 批次 | 文本 | 来自 keywords.csv 的 batch |
| 发布日期 | 日期时间 | 发布成功时写入 |
| 状态 | 单选 | 只有两个选项：待发布、已发布 |
| devto链接 | 链接 | 主 dev.to |
| devto链接_2 | 链接 | 副 dev.to |
| CodeLegion链接 | 链接 | 主 CodeLegion |
| CodeLegion链接_2 | 链接 | 副 CodeLegion |
| Medium链接 | 链接 | 已开启时回填 |
| Zenn链接 | 链接 | 日语平台，未开启时留空 |
| Qiita链接 | 链接 | 日语平台，未开启时留空 |

发布成功后只更新这一行的链接、状态和发布日期。找不到唯一对应的关键词时，停止写入，不要新建重复行。

完成标准：表已建好，11 个表头名称与上表一致，`DINGTALK_BASE_ID` 和 `DINGTALK_TABLE_ID` 已写入 `keys.env`，并且 `dws aitable field get` 能读到这些字段。

## 第 8.1 步：确认写文章规则

写文章前必须读 `references/writing-rules.md`。文末引流链接来自 `product.yaml` 的 `footer_links`。这一节为空时，停止并询问使用者要放哪些链接，不要省略文末，也不要编造链接。

完成标准：`footer_links` 至少有 1 条使用者确认过的链接，且写文章规则已按该文件执行。

## 第 9 步：部署到服务器

告诉使用者：每天自动跑必须放在一台常开的服务器上。个人电脑关机、对话结束、笔记本休眠，都不会继续发文。

向使用者要：

1. 服务器登录方式。不要把密码或私钥贴进技能包。
2. 服务器时区。定时任务按服务器本地时间跑，目标是每天 10:00。
3. 服务器能访问已开启平台的发布接口。GitHub 若 443 不通，改用 SSH 部署密钥，不要换公共代理。

要做：

1. 把技能目录同步到服务器，例如 `/opt/product-daily-publisher/`。
2. 把 `~/.config/product-daily-publisher/` 同步到服务器同一路径。权限保持 `600`。不要把配置提交到 Git。
3. 在服务器安装运行所需命令：`python3`、发文脚本依赖、钉钉 CLI `dws`、模型调用所需命令。
4. 用只读命令再做一次第 7 步账号核对。

完成标准：服务器上技能和配置都在，账号核对通过，配置文件不在 Git 仓库里。

## 第 10 步：安装每天 10:00 的定时任务

在服务器创建系统定时任务，不要只写在个人电脑的 crontab。

规则：

- 每天 10:00 启动当天任务。
- 若 10:00 没发出去，当天继续重试到 21:30。
- 当天已经成功，则后续触发直接跳过，不能重发。
- 定时任务的 PATH 必须包含实际要用的命令目录。
- 日志写到服务器的 `state/` 目录，不写密钥。

完成后执行一次只读检查：打印下一次触发时间、时区、日志路径。不要为了测试而真实发文，除非使用者明确说「现在发一篇测试」。

完成标准：定时任务已安装，时区是使用者确认的本地时间，下一次 10:00 会启动，且成功标记能阻止重复发文。

## 第 11 步：向使用者汇报

只汇报这些：

- 已开启的平台
- 每天几个关键词、每个平台发几篇
- 服务器上的定时任务是否安装成功
- 下一次自动运行时间
- 仍缺的配置，若没有就写「无」

不要汇报密钥、令牌、服务器密码或私钥。

未完成第 10 步之前，不要说「已经会每天自动发」。
